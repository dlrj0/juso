# 사진 이름 → 촬영 주소로 변경 프로젝트 (인수인계 요약, 최신)

> 새 Claude 세션에 이 파일과 `photo_rename.ps1`, `photo_rename.bat`을 올리고 맨 아래 "요청문"을 사용하세요.
> 최종 갱신: 2026-11-27 (v8.6: 메뉴 1·2·4가 하위 폴더 1단계까지 처리, 캐시·로그 없이도 동작. 이전 v8: 지도를 Leaflet/OSM/Esri에서 **카카오 지도 JavaScript SDK**로 교체(지적편집도·스카이뷰·클러스터). 이전 v7.2: 지도에 '이름 없는 사진 찾기' 상자 추가. v7.1: 파일 이름에 좌표 넣기/빼기 선택. v7: 메뉴 4번 폴더 정리 추가. 이전 v6: 지도 카카오 링크·지도에서 이름 직접 바꾸기·예시 주소 가짜로 교체. 이전 v5.1: 화면 문구 간소화, 지도 보기 기능 반영, 코드 점검·카카오 규격 재확인 결과 포함)

## 1. 목표
- 삼성폰으로 찍은 사진(위치 태그 켬) 2천 장 이상의 파일 이름을 **촬영 위치의 지번 주소 + 좌표**로 일괄 변경 (Windows, bat/ps1 방식).
- 결과 예: `○○도 ○○시 ○○면 ○○리 123-4 (1) 37.123456, 127.123456.jpg` (※ 문서·코드의 예시는 항상 가짜 주소 사용)
  - 같은 주소 사진은 `(1)`, `(2)` … 번호, 번호 뒤에는 **그 사진 자신의 위도, 경도**(소수 6자리)
- 2천 장이라 사전 테스트 없이 쓰려 했으므로 안전장치(미리보기, 로그, 되돌리기)가 중요.
- 처음 보는 사람도 쓸 수 있게 **기능은 최소**, 안내는 화면에 직접 표시.

## 2. 파일 구성 (현재)
| 파일 | 역할 |
|---|---|
| `photo_rename.ps1` | 프로그램 전부 (GPS 확인·주소 조회·이름 변경·되돌리기·지도 보기). UTF-8 BOM + CRLF (v8 점검 완료: BOM 있음, 모든 줄 CRLF) |
| `photo_rename.bat` | 더블클릭 실행용 3줄 런처 (`powershell`=Windows PowerShell 5.1, 실행 정책 우회, `chcp` 없음). ps1과 같은 폴더에 둘 것. 폴더를 bat 위로 끌어다 놓으면 그 폴더로 시작 |

예전 `check_gps.bat/.ps1`, `설정.txt`는 폐기(기능 흡수). 예전 `설정.txt`/`kakao_key.txt`의 API 키는 자동으로 가져옴.

실행 중 생성되는 파일:
- `kakao_api_key.txt` (스크립트 폴더) — 확인된 **REST API 키** 자동 저장 (주소 조회용)
- `kakao_js_key.txt` (스크립트 폴더) — **JavaScript 키** (지도용, 메뉴 3 첫 실행 때 한 번 입력·저장). 지도 오류 상자의 "저장된 JavaScript 키 지우기" 버튼으로 삭제 가능
- `address_cache.txt` (스크립트 폴더) — 좌표→주소 캐시(`위도,경도<TAB>주소`). 중간에 멈춰도 이어서 진행. 지도(3번)와 이름 바꾸기(1번)가 **같이 사용**
- `폴더정리로그_날짜.csv` (사진 폴더) — 4번 폴더 만들기 기록(OldPath/NewPath/Created). 폴더 없애기 후 `되돌림완료_` 접두사
- `이름변경로그_날짜.csv` (사진 폴더) — OldPath/NewPath, 되돌리기용. 되돌리면 `되돌림완료_` 접두사가 붙어 다음 되돌리기는 그 이전 기록을 대상으로 함
- `건너뜀목록_날짜.txt` (사진 폴더) — GPS 없음/읽기 실패/주소 못 찾음 사진

## 3. 사용자 흐름
메뉴: **1 이름 바꾸기 / 2 되돌리기 / 3 사진 위치를 지도로 보기 / 4 폴더 정리**

1. 상단 설명(무엇을 하는지, 결과 예시, 원본 안전·되돌리기 가능) → 메뉴 선택
2. 폴더: 현재 폴더(bat 위치)를 표시, Enter=그대로 / 다른 경로 붙여넣기 (폴더 선택 창은 루트부터 시작해 불편하여 제거)
3. (이름 바꾸기) API 키: 없으면 터미널에 붙여넣기 → 서울시청 좌표로 테스트 → 성공 시 저장. 401/403이면 재입력, 그 외 오류는 서버 메시지+힌트 출력 후 종료
4. **1단계 GPS 확인**: `사진 N장 중 GPS 있음 M장` 한 줄 + (있을 때만) GPS 없음 / 읽기 실패 / 이미 주소 이름 개수. 전부 GPS가 없으면 원인 안내 후 종료
5. **2단계 주소 조회**: 카카오 `coord2address`(지번 우선, 없으면 도로명). 이미 `주소 (번호)` 형식인 사진은 **이름에서 주소를 가져와 API 호출 생략**
6. 변경 계획(바뀔 수 + 해당될 때만 이미 올바름/건너뜀 개수, 예시 3개) → **Y 입력 시에만** 실행
7. 실행 전 로그 CSV 저장 → 임시 이름(`__tmp_*`)을 거치는 2단계 이동으로 충돌 방지, 실패 시 원래 이름 복구 시도
8. 되돌리기: 폴더의 가장 최근 로그 기준으로 원래 이름 복원
9. **지도 보기(3번)**: 먼저 JavaScript 키가 없으면 입력받음(REST 키와 같은 값이면 거부). 폴더의 GPS 있는 JPG를 읽어 내 PC 안 **`http://localhost:8765`(포트 고정)** 에 작은 웹서버를 띄우고 브라우저로 카카오 지도를 엶. 창에서 Enter를 누르면 종료. 인터넷 필요. **이전 지도 PowerShell 창이 열려 있으면 8765가 이미 사용 중이라 시작 실패 → 그 창에서 Enter로 닫고 다시 실행**

### 지도(HTML) 내용 — 코드 점검 결과
- **카카오 지도 JavaScript SDK**(`dapi.kakao.com/v2/maps/sdk.js?appkey=JS키&autoload=false&libraries=clusterer`). 오른쪽 위 상자: 일반 지도 / 스카이뷰(`HYBRID`, 위성+지명) 전환, **지적편집도(`USE_DISTRICT`, 필지 경계) 켜기/끄기**, 지번 표시, 사진 위치 켜기/끄기
- **(v8.3) 카카오 클러스터러는 쓰지 않음.** 직접 묶음: 화면에서 14px 안의 사진을 한 핀으로 묶고(`refreshView`, 이동·확대 후 `idle`마다 다시 계산), 멀리서나 가까이서나 같은 모양. 빨강=묶음 안 전부 이름에 주소 있음, 파랑=이름 없는 사진 포함, 숫자=장수(1장이면 숫자 없음). 묶음을 누르면: 거의 같은 자리(6px 이하)면 목록, 아니면 그 사진들이 보이게 확대. 지번 글자는 레벨 4 이하에서 사진 많은 핀부터 놓되 겹치면 생략(확대하면 나타남)
- 점을 누르면 정보가 **오른쪽 상자**(지도 위 말풍선 아님)에 나옴. 눌린 점에 노란 고리 표시
- 키/도메인이 틀리면(SDK 로드 실패 또는 10초 안에 안 열림) 지도 위에 **원인 안내 상자**가 뜸
- 사진 1장 = 점 1개. **점을 누르면 파일명, 주소, 촬영 시각, 좌표(소수 6자리), 사진 미리보기, 구글맵/카카오맵 링크**가 나옴
- 9px 안에 겹친 점은 목록으로 묶어 선택. 지도 위 글자는 **지번(예: 123-4)+장수만** 표시(카카오 레벨 4 이하로 확대 시). 좌표는 상세 상자에서만 보임
- 팝업 주소 출처 우선순위: 파일 이름의 주소 > `address_cache.txt` > (저장된 API 키가 있으면) 카카오 조회. 키가 없으면 주소 없는 사진은 지번 라벨이 비어 있음
- 중요: 지도의 주소는 이름 바꾸기와 **같은 출처**라서 "주소가 맞는지"를 독립적으로 검증해 주지는 않음. 맞는지 보려면 팝업의 좌표를 구글맵/카카오맵에서 직접 열어 비교

### 지도에서 이름 직접 바꾸기 (v6)
- 팝업의 "이름 직접 바꾸기" 칸에 **지번까지 주소**를 입력 → 그 사진이 `주소 (번호) 위도, 경도.jpg`로 바뀜. 주소 없는 사진은 칸이 자동으로 펼쳐지고, 가장 가까운 사진의 주소(지번 제외)가 미리 들어감
- 안전장치: ① 지도 서버가 실행될 때마다 만드는 일회용 토큰이 맞아야만 처리(다른 웹페이지의 요청 차단) ② 주소는 한글로 시작·숫자로 끝, 금지문자·길이 검사 ③ 같은 이름이 있으면 덮어쓰지 않음 ④ `이름변경로그_지도_날짜.csv`에 기록 → **2번(되돌리기)** 으로 복구 가능 ⑤ **(v8.1) 바꿀 때마다 같은 주소 사진 전체를 촬영 시각 순(EXIF, `$NewestFirst` 설정 따름)으로 (1),(2)… 자동 재번호**. 다른 사진의 이름도 바뀌며 전부 같은 로그 CSV에 기록되어 2번으로 되돌릴 수 있음. 주소를 바꾸는 경우 예전 주소 쪽도 번호를 다시 매김(빈 번호 메움). 메뉴 1과 같은 규칙
- 주의: 사진 자체의 좌표는 바뀌지 않음. 지번은 사용자가 입력한 값을 그대로 믿음(검증 없음)

### 이름 없는 사진 찾기 (v7.2, 지도)
- "이름 없는 사진" = **파일 이름에 주소가 없는 사진**(주소를 캐시/카카오로 알아냈어도 이름이 안 바뀐 사진 포함). 지도 데이터의 `r`(1=이름에 주소 있음)로 구분
- 점 색: 이름에 주소 있음=빨강(작게), 없음=파랑(크게, 위에 그림). 왼쪽 위 상자: 장수, **이름 없는 사진만 보기** 체크, **◀ 이전 / 다음 ▶**(끝에서 순환, 눌러서 그 사진으로 이동·팝업 열림), 목록(눌러서 이동)
- 팝업에서 이름을 바꾸면 그 점이 빨강으로 바뀌고 목록에서 빠짐. 다음을 누르면 방금 바꾼 사진 바로 뒤 것으로 이동. 전부 바꾸면 "이름 없는 사진 없음 ✔"이 되고 보기 모드는 자동 해제
- 이름이 없는 사진의 팝업은 이름 입력칸이 자동으로 펼쳐짐(주소를 아는 경우 그 주소가 미리 들어감)
- 메뉴 3 시작 시 콘솔에 이름 없는 사진 수를 표시. GPS가 없는 사진은 지도에 점이 없으므로 이 기능에 안 나옴(건너뜀목록에서 확인)
- 검증: v8에서 가짜 카카오 SDK(jsdom)로 표시·필터·이전/다음·이름 바꾼 뒤 갱신·지도 종류/지적편집도 전환·오류 상자를 실행해 확인. **실제 카카오 SDK/브라우저/Windows에서는 미확인**

### 이름에 좌표 넣기/빼기 (v7.1)
- 메뉴 1(이름 바꾸기)과 메뉴 3(지도)에서 **1 넣기 / 2 빼기**를 매번 물음. 넣기=`주소 (1) 위도, 경도.jpg`, 빼기=`주소 (1).jpg`
- 이미 바뀐 사진에 1번을 다시 실행해도 **원래 이름으로 돌아가지 않음**: 이름 속 주소를 그대로 쓰고 API를 다시 부르지 않기 때문(캐시 때문이 아님). 좌표는 사진 EXIF에서 다시 읽으므로 빼기 → 넣기로 언제든 오갈 수 있음. 같은 주소끼리 번호는 재정렬됨
- 다시 실행할 때마다 `이름변경로그_*.csv`가 새로 생김. 2번(되돌리기)은 **가장 최근 로그 한 단계씩**만 되돌림(좌표 빼기 → 2번 → 좌표 있는 이름, 한 번 더 2번 → 처음 이름)
- 이 버전은 Windows에서 실행해 보지 못함

### 폴더 정리 (v7, 메뉴 4)
- 4 → **1 폴더 만들기 / 2 폴더 없애기**. 둘 다 **계획(폴더별 장수, 예시)을 먼저 보여주고 Y일 때만 실행**
- 만들기: 단위 선택 `1 도 / 2 시/군/구 / 3 읍/면/동 / 4 리`. 폴더 이름은 **그 단계까지의 주소 전체**를 한 단계 폴더로 만듦(겹겹이 아님). 예) 4번 선택 → `○○도 ○○시 ○○면 ○○리\` 폴더에 사진 이동
- 주소는 **파일 이름의 주소**에서 읽음(API 호출 없음, 키 불필요). 이름에 주소가 없는 사진(건너뛴 9장 등)은 **원래 자리에 그대로 둠**
- 주소 분리 규칙: 맨 끝 지번(`123-4`, `산 12-3`) 제외 → 첫 토큰=도, 뒤따르는 `시/군/구`로 끝나는 토큰들=시/군/구(예: `수원시 팔달구`), 그 다음 `읍/면/동/가`로 끝나는 토큰=읍/면/동, 그 다음 `리`로 끝나는 토큰=리. 파이썬 이식본으로 서울·경기·세종·제주·산 번지 예시 확인함
- 고른 단계가 주소에 없으면(예: 동 지역에 리 선택, 세종시) **있는 단계까지만**으로 폴더를 만들고 계획 화면에 개수를 표시
- 같은 이름이 이미 폴더에 있으면 덮어쓰지 않고 건너뜀. 이동은 임시 이름 없이 1단계 직접 이동
- 없애기: 가장 최근 `폴더정리로그_*.csv` 기준으로 사진을 원래 자리로 이동, **이 프로그램이 새로 만든 폴더만** 비었을 때 삭제(다른 파일이 있으면 남김)
- 주의: ① 폴더로 옮긴 사진은 1·3번에서 안 보임(폴더 경로를 직접 지정하면 그 폴더만 처리) ② **되돌릴 때는 역순**: 폴더 없애기(4-2) → 이름 되돌리기(2). 폴더에 옮긴 상태에서 2번을 하면 "되돌릴 사진 0장"이 나옴(안내 문구 추가함)
- 이 버전은 Windows에서 실행해 보지 못함(괄호 균형·인코딩 점검과 주소 분리 규칙 시험만 함)

### 이미 바뀐 이름 인식 규칙
정규식: 한글로 시작, 숫자로 끝나는 주소 + ` (번호)` + (선택) ` 위도, 경도`. 예전 `주소 (n)` 형식도 인식하여 좌표를 붙여 새 형식으로 바꿈. 다시 실행하면 같은 주소끼리 번호가 재정렬됨.
- 주의: 이미 이 형식인 파일은 **이름 속 주소를 그대로 믿고** 카카오를 다시 부르지 않음. 예전 버전이 만든 잘못된 주소가 있으면 재실행해도 안 고쳐지므로, **먼저 2번(되돌리기)** 으로 원래 이름으로 돌린 뒤 다시 할 것.
- (확인) `산 12-3` 같은 산 번지, `태평로1가 31` 같은 숫자 섞인 동 이름도 정상 인식·지번 추출됨.

### 번호 순서
- 기본: 가장 오래된 사진 = (1). 최근 사진을 (1)로 하려면 ps1 상단 `$NewestFirst = $true`.
- 사용자의 원래 요청이 모순되어 있어 **최종 선호는 미확정**.

## 4. 합의된 개념 / 확인된 사실
- 사진(EXIF)에는 **좌표만** 있고 주소는 없음. 주소는 좌표를 변환한 것. 이름을 바꿔도 EXIF 좌표는 유지됨.
- 번지 경계 근처에서는 GPS 오차로 옆 번지로 나뉠 수 있음.
- **GPS가 없던 문제의 원인은 전송 방식**이었음: GitHub에 zip으로 올려 받은 사진은 GPS가 보임. 카톡·메신저·일부 클라우드·브라우저는 위치 정보를 제거할 수 있음 → 폰의 `DCIM\Camera`를 USB로 복사하거나 Smart Switch 권장. HEIC는 미지원(JPG만).
- **카카오 API 규격 (2026-11-27 공식 문서로 재확인)**
  - `GET https://dapi.kakao.com/v2/local/geo/coord2address.json`, 헤더 `Authorization: KakaoAK {REST API 키}`
  - **x = 경도(longitude), y = 위도(latitude)** → 코드의 `x=$lon&y=$lat` 순서가 맞음
  - 응답 `documents[0].address.address_name` = 전체 지번 주소, `road_address`는 도로명. 산 번지는 `address_name`에 "산"이 포함됨(예: `신림동 산 56-1`). 응답은 `application/json;charset=UTF-8`
  - 반드시 **REST API 키**, 앱의 [카카오맵] > [사용 설정] ON. REST 키의 [호출 허용 IP 주소]가 설정돼 있으면 해당 IP 외에서 `ip mismatched`(401). 도메인 제한은 JavaScript 키에만 해당
  - **무료 쿼터**: "좌표로 주소 변환" 일 100,000건, 전체 API 월 3,000,000건 → 2천 장은 충분. 소진 시 429. 초과분 유료는 0.5원/건. 2026-07-21 이후 카카오맵을 처음 활성화한 앱은 **개발자 계정에서 첫 번째로 활성화한 앱에만** 무료 쿼터 제공(앱 정보에 [카카오맵 무료 쿼터] 뱃지)
- **주소 정확도**: 갤럭시 갤러리 주소와 카카오 결과의 지번이 서로 다르게 나온 사례 있음(같은 리 안의 인접 지번). 좌표 반올림 때문이 아니고(캐시 키에만 소수 6자리 사용, 요청은 전체 정밀도), 서비스별 주소 선정 기준 차이와 시골의 큰 필지+GPS 흔들림 때문일 가능성이 큼. 카카오도 2022년 개편 공지에서 같은 좌표의 지번이 바뀐 사례를 공개한 적 있음(지번 선정 기준 자체가 서비스·시기별로 달라질 수 있음). 사용자 결정: **카카오 지번 그대로 사용**. 갤러리 주소와 완전히 맞추려면 다른 서비스(구글 지오코딩 등, 키/결제 필요) 비교가 필요.

- 오래된 `address_cache.txt`가 있으면 이전 버전 결과가 섞여 있을 수 있으므로, 본 작업 전에 지우고 새로 조회하는 것이 안전.

- **주소 못 찾음(9장) 처리 권장 순서**: 건너뜀목록의 좌표·지도 링크로 위치 확인 → 메뉴 3 지도에서 해당 점의 "이름 직접 바꾸기"로 지번 입력(가까운 사진 주소가 미리 들어감) → 그 다음 메뉴 4로 폴더 정리. (자동으로 옆 지번을 붙이는 기능은 옆 필지 오배정 위험 때문에 만들지 않음)

- **카카오 지도 설정 (v8)**: ① 카카오 개발자 사이트 [플랫폼 키] > JavaScript 키 > [JavaScript SDK 도메인]에 `http://localhost:8765` 등록 ② [카카오맵] 사용 설정 ON ③ 지도 SDK에 REST 키를 쓰면 오류(공식 문서). **도메인 등록에 포트(`:8765`)까지 넣어야 하는지는 확정하지 못함** — 지도가 안 뜨면 `http://localhost`도 함께 등록해 볼 것. 키가 틀리면 지도가 비고 안내 상자가 뜸.
- 카카오 지도 이용약관(지도 위 데이터 표시·캐시 관련)은 읽어 보지 못함. 개인 사진 정리 용도.

## 8. 권장 테스트 절차 (본 작업 전)
1. 2천 장 원본 폴더를 **통째로 백업(복사)**
2. 새 폴더에 사진 5~10장 복사 (GPS 있는 것/없는 것 섞어서) + bat/ps1 복사. (이전 `address_cache.txt`가 있으면 삭제)
3. `photo_rename.bat` 실행 → **3(지도)** → JavaScript 키 입력 → 점이 올바른 위치에 찍히는지, 지적편집도·스카이뷰가 켜지는지, 팝업 좌표와 주소를 구글맵/카카오맵과 비교
4. 다시 실행 → 1 → 키 입력 → GPS 확인 화면과 변경 예시 확인 → Y
5. 파일명 결과 확인(주소, 번호, 파일명 속 좌표 = 지도 팝업 좌표) → 다시 실행해 2(되돌리기)로 복구되는지 확인
6. (폴더 정리) 4 → 1 → 단위 선택 → 계획 확인 → Y → 폴더 확인 → 4 → 2로 원상 복구되는지 확인
7. 이상 없으면 본 폴더에 적용. 여러 번 실행했다면 되돌릴 때 가장 최근 기록부터 차례로 진행

